01 · La idea esencial

¿Qué hace PDF Inspector?

PDF Inspector es una biblioteca abierta de Firecrawl escrita en Rust. Clasifica documentos, extrae texto respetando su posición y convierte PDF con texto nativo en Markdown estructurado, sin utilizar OCR.

Clasifica

¿Qué tipo de PDF es?

Distingue documentos con texto, escaneados, basados en imágenes o mixtos, y devuelve una puntuación de confianza.

Extrae

Texto con estructura

Reconoce columnas, títulos, listas, enlaces, estilos, tablas y orden de lectura.

Decide

¿Qué páginas van a OCR?

Devuelve las páginas que no tienen una capa de texto fiable para procesar solo esas con OCR.

Lo que no hace: PDF Inspector no incluye OCR. Si el archivo es una fotografía, un escaneo o tiene una codificación rota, necesitarás conectarlo a Tesseract, Google Document AI, Azure, AWS Textract, Mistral OCR u otro sistema.

¿Para qué sirve?

RAG y agentes

Convierte informes, normativa, papers y manuales en Markdown antes de fragmentarlos y generar embeddings.

Facturas y contratos

Extrae documentos con texto real localmente y reserva el OCR para páginas escaneadas.

Privacidad

La extracción local evita enviar a terceros los PDF que ya se pueden leer desde su propia estructura.

03 · La prueba más directa

Usarlo desde la terminal

La herramienta de terminal requiere Rust y Cargo. Instala Rust desde su web oficial y después instala PDF Inspector:

cargo install pdf-inspector

Convertir un PDF a Markdown

pdf2md documento.pdf > documento.md

Comandos útiles

La primera prueba: utiliza un PDF generado desde Word y otro escaneado con el móvil. El primero debería producir Markdown; el segundo debería quedar marcado para OCR.
04 · Ruta recomendada para IA

Usarlo con Python

1. Crear un entorno e instalar

python -m venv .venv # Windows: .venv\Scripts\activate # macOS / Linux: source .venv/bin/activate python -m pip install --upgrade pip pip install pdf-inspector

El paquete oficial publica ruedas precompiladas para CPython 3.8 o superior en las principales plataformas indicadas en su documentación. En otras plataformas puede ser necesario compilar con Rust.

2. Script completo: PDF → Markdown u OCR

from pathlib import Path import pdf_inspector origen = Path("documento.pdf") salida = origen.with_suffix(".md") resultado = pdf_inspector.process_pdf(str(origen)) print("Tipo:", resultado.pdf_type) print("Confianza:", resultado.confidence) print("Páginas:", resultado.page_count) print("Necesitan OCR:", resultado.pages_needing_ocr) if resultado.markdown: salida.write_text(resultado.markdown, encoding="utf-8") print("Markdown guardado en:", salida) else: print("No hay Markdown fiable. Envía las páginas indicadas a OCR.")

3. Solo detectar, sin extraer

import pdf_inspector resultado = pdf_inspector.detect_pdf("documento.pdf") if resultado.pdf_type == "text_based": print("Se puede extraer localmente") else: print("Páginas para OCR:", resultado.pages_needing_ocr)
También admite bytes: utiliza process_pdf_bytes() cuando el archivo llega desde una API, un formulario o un almacenamiento y no quieres guardarlo primero en disco.
05 · Para aplicaciones JavaScript

Usarlo con Node.js

mkdir prueba-pdf cd prueba-pdf npm init -y npm install @firecrawl/pdf-inspector

Script completo

import { readFileSync, writeFileSync } from 'node:fs'; import { processPdf } from '@firecrawl/pdf-inspector'; const pdf = readFileSync('documento.pdf'); const resultado = processPdf(pdf); console.log('Tipo:', resultado.pdfType); console.log('Confianza:', resultado.confidence); console.log('Páginas para OCR:', resultado.pagesNeedingOcr); if (resultado.markdown) { writeFileSync('documento.md', resultado.markdown, 'utf8'); console.log('Markdown guardado'); }
Compatibilidad: la documentación del paquete Node enumera binarios precompilados para Linux x64, macOS ARM64 y Windows x64. Comprueba tu arquitectura si la instalación falla.
06 · El PDF no sale del navegador

Usarlo con WebAssembly

La versión WASM ejecuta el parser dentro del navegador. Los bytes del PDF no se suben a un servidor por el hecho de usar la biblioteca.

npm install @firecrawl/pdf-inspector-wasm
import init, { processPdf } from '@firecrawl/pdf-inspector-wasm'; await init(); const respuesta = await fetch('/documento.pdf'); const pdf = new Uint8Array(await respuesta.arrayBuffer()); const resultado = processPdf(pdf, { profile: 'compact', includePageMarkers: true }); console.log(resultado.pdfType); console.log(resultado.markdown);
Documentos grandes: el procesamiento es síncrono después de init(). La documentación recomienda utilizar un Web Worker para no bloquear la interfaz.
07 · Entender la respuesta

Los cuatro tipos de PDF

TextBased

Texto nativo

El documento contiene operadores de texto. Es el mejor candidato para extracción local rápida.

Scanned

Documento escaneado

Las páginas se comportan como fotografías del papel. Necesitan OCR.

ImageBased

Basado en imágenes

Predominan imágenes sin una capa de texto útil. Debe pasar por visión u OCR.

Mixed

Documento mixto

Algunas páginas se extraen directamente y otras deben enrutarse a OCR.

Campos importantes

CampoQué significaQué hacer
pdf_type / pdfTypeClasificación generalElegir extracción u OCR
confidenceConfianza entre 0 y 1Aplicar un umbral prudente
pages_needing_ocrPáginas sin texto fiableEnviar solo esas a OCR
has_encoding_issuesPosible fuente o codificación rotaValidar el texto y considerar OCR
pages_with_tablesPáginas con tablas detectadasRevisar el Markdown resultante
is_complex_layoutColumnas o estructura complejaAplicar controles de calidad
Cuidado con la numeración: algunas respuestas ligeras de clasificación documentan páginas en base 0, mientras que otros resultados agregados utilizan base 1. Comprueba el tipo de función antes de mostrar o enviar páginas a OCR.
08 · El ahorro real

Enrutamiento inteligente de OCR

Llega el PDF
PDF Inspector clasifica
¿Texto fiable?
Sí → Markdown local
No → OCR selectivo

Regla de decisión recomendada

SI tipo = text_based Y confianza alta Y no hay problemas de codificación: usar Markdown local SI NO: enviar solo pages_needing_ocr al OCR unir los resultados respetando el orden de páginas
No confíes únicamente en el tipo. Valida que el texto tenga longitud razonable, caracteres legibles y una estructura coherente. Un PDF puede contener una capa de texto defectuosa.

Según el benchmark publicado por el propio proyecto el 31 de julio de 2026, PDF Inspector obtuvo una puntuación global de 0,875 y procesó el corpus de 200 documentos en 0,470 s bajo su configuración de prueba, con OCR desactivado. Es una medición del proyecto: reproduce el ensayo con tus propios documentos antes de tomar decisiones de producción.

09 · La arquitectura friki

n8n, Supabase y RAG

PDF Inspector encaja como filtro de entrada: evita gastar OCR y tokens en documentos que ya contienen texto estructurado.

Formulario / Drive
Inspector PDF
Switch por tipo
Markdown u OCR
Chunks → Supabase

Flujo recomendado

  1. Recibe el archivo mediante formulario, Drive, correo o webhook.
  2. Guarda el PDF en un almacenamiento temporal con identificador único.
  3. Llama a un microservicio Python/Node que ejecute PDF Inspector.
  4. Usa un nodo Switch con pdf_type, confianza y errores de codificación.
  5. Ruta A: Markdown local. Ruta B: OCR únicamente para las páginas marcadas.
  6. Normaliza, divide por títulos/páginas y genera embeddings.
  7. Guarda texto, página, documento, hash, permisos y procedencia en Supabase.
En n8n autoalojado: puedes preparar un contenedor con el CLI o un servicio lateral. Para mantener el flujo estable, es preferible exponer una pequeña API interna que reciba bytes y devuelva JSON, en lugar de instalar dependencias nativas dentro de cada nodo.

Respuesta JSON mínima de tu servicio

{ "document_id": "abc-123", "pdf_type": "mixed", "confidence": 0.94, "page_count": 18, "pages_needing_ocr": [4, 11], "has_encoding_issues": false, "markdown": "# Título..." }
10 · Diagnóstico rápido

Problemas frecuentes

“No se encuentra pdf2md”

Comprueba que cargo install terminó y que la carpeta binaria de Cargo está incluida en PATH.

El Markdown sale vacío

Clasifica el documento. Si está escaneado o basado en imágenes, el resultado esperado es enviarlo a OCR.

Caracteres extraños

Consulta has_encoding_issues. Algunas fuentes CID carecen de un mapa Unicode fiable.

Las columnas se mezclan

Revisa is_complex_layout y las páginas con columnas. Compara visualmente antes de ingerir en un RAG.

Falla npm

Verifica sistema y arquitectura. El paquete Node documenta un conjunto concreto de binarios precompilados.

La web se congela

Mueve la versión WASM a un Web Worker cuando proceses archivos grandes.

Registro avanzado en Rust

RUST_LOG=pdf_inspector=debug cargo run --bin pdf2md -- documento.pdf > /dev/null
11 · Antes de producción

Privacidad y seguridad

Archivos no confiables

Limita tamaño, páginas, tiempo y memoria. Procesa documentos externos en un servicio aislado y actualizado.

Datos personales

Define conservación, borrado, controles de acceso, registro de actividad y base jurídica. Procesar localmente ayuda, pero no sustituye el RGPD.

OCR externo

Si envías páginas a un proveedor, revisa ubicación, contrato, subencargados, retención y uso de los datos.

  • Calcula un hash para detectar duplicados y mantener trazabilidad.
  • No guardes archivos sensibles en carpetas públicas ni en logs.
  • Elimina los temporales al terminar y cifra el almacenamiento.
  • Valida el Markdown antes de usarlo como contexto para una IA.
  • Fija versiones y prueba antes de actualizar.
